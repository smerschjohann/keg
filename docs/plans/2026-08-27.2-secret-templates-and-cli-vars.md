## 0. Ausgangslage & Motivation

### 0.1 Ist-Zustand

1. **`secret_sources.cmd`:** Befehlslisten in `secret_sources` (z. B. `cmd: ["genkey", "keg", "1500"]`) wurden zuvor statisch ohne Template-Auswertung ausgeführt. Dynamische Parameter (z. B. instanzspezifische Tokens via `genkey <instance> <ttl>` oder variable Vault-Pfade) erforderten feste Strings oder externe Wrapperskripte.
2. **Template-Variablen (`.Vars`):** Variablen konnten im Repo (`vars:`), global in der User-Config (`vars:`), pro Repo-Match (`repos[match].vars:`) und via Host-Umgebung (`KEG_VAR_<NAME>`) gesetzt werden. Es existierte jedoch **kein direktes CLI-Flag**, um Variablen beim Aufruf von `keg run` flexibel zu übergeben oder zu überschreiben.

### 0.2 Ziel (Soll)

* **Go-Template-Rendering in `secret_sources`:** Argumente in `secret_sources[<name>].cmd` werden vor der Host-Ausführung über [`internal/template.Apply`](file:///home/coder/dev/keg/internal/template/template.go#L47) gerendert.
* **Standard-Kontext für Secrets:**
  * `{{ .Vars.instance }}`: Name der Sandbox-Instanz (aus `--name` / `-n` oder generierte ID).
  * `{{ .Vars.secret_name }}`: Name des jeweiligen Secrets (z. B. `ai_secret_key`).
  * `{{ .Vars.repo_dir }}`: Host-Wurzelverzeichnis des Repositories.
  * Reguläre gemergte `.Vars` (und `.Env`, falls `template_env.allow_env: true`).
* **Subprozess-Host-Environment:** `runCmd` setzt zusätzlich `KEG_INSTANCE`, `KEG_SECRET_NAME` und `KEG_REPO_DIR` in `c.Env`.
* **CLI-Flag `--var` (`-V`):** `keg run --var key=value` (wiederholbar) schleust Variablen mit **höchster Priorität** in die Template-Engine ein.

## 1. Entwurfsentscheidungen & Spezifikation

### 1.1 Konfiguration in `~/.config/keg/config.yaml`

```yaml
vars:
  token_ttl: "1500"

secret_sources:
  ai_secret_key:
    # Go-Template mit Fallback-Funktion:
    cmd: ["/home/coder/.local/bin/genkey", '{{ .Vars.instance | default "keg" }}', '{{ .Vars.token_ttl | default "1500" }}']
    interval: 10m
    timeout: 5s
    always: true
```

### 1.2 CLI-Syntax & Precedence für `--var`

```bash
# Setzt token_ttl=1800 und custom_var=foo für alle Templates und Secret-Commands
keg run --var token_ttl=1800 -V custom_var=foo -n my-agent
```

**Rangfolge für `vars:` (später gewinnt):**
1. Repo-`.keg.yaml` (`vars:`)
2. Globale User-Config (`vars:`)
3. Repo-Match in User-Config (`repos[<match>].vars:`)
4. Host-Environment `KEG_VAR_<NAME>`
5. **CLI-Flags `--var / -V`** *(höchste Priorität)*

### 1.3 Validierung & Fehlerbehandlung

* `--var` erwartet zwingend das Format `KEY=VALUE`. Leere Schlüssel (`=value`) oder Flags ohne `=` werfen einen klaren CLI-Validierungsfehler vor Start der Sandbox.
* Ungültige Template-Referenzen ohne Default (z. B. `{{ .Vars.nicht_definiert }}`) führen über die bestehende Template-Validierung zu einem sauberen Fehler mit Zeilen- und Namenshinweis.
